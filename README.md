# 林宇航 · Designer Portfolio

林宇航的个人体验设计作品集，用一个可直接浏览的网页呈现视觉设计、体验设计与 AI 设计探索相关项目。

作品集不只是项目截图的集合，而是将项目封面、详情页、交互状态、动效反馈与个人经历组织在同一个可运行的浏览路径中，让设计成果能够通过真实操作被理解和验证。

## 运行与体验

- 在线演示：<https://aerol1n.github.io/Linyuhang-Design-Portfolio/>
- 推荐环境：Chrome / Edge 最新版本
- 推荐分辨率：桌面端 1440px 及以上
- 本地入口：`index.html`

本项目为静态网站，无需构建步骤。直接打开 `index.html` 即可浏览；为获得更稳定的媒体加载与跨页面体验，也可以通过任意静态文件服务运行项目目录。

## 项目目标

- 用真实页面呈现视觉设计与体验设计成果，减少只依赖静态截图产生的理解偏差。
- 将作品流、项目导航、详情浏览、About Me 与联系入口组织为连续的阅读路径。
- 通过状态切换、悬浮反馈和页面转场补足静态视觉稿难以表达的体验细节。
- 在保持视觉表现力的同时，兼顾响应式布局、键盘访问和信息层级的一致性。

## 作品范围

当前作品集包含以下项目：

- 0-1 搭建百度AI 作品管理平台：从 0 到 1 的产品体验与视觉定义探索。
- AI Coding 交付实践：独立开发、Design-to-Code 与动效工程化实践。
- 小呆耶达App & Web 端：用户研究、多端协同与视觉主导的产品升级。
- AI 辅助品牌视觉设计：AIGC 驱动的角色与品牌设计探索。
- 其他项目：视觉设计与 AI 设计探索的项目集合。

页面还包含个人简介、经历、奖项、联系方式、GitHub 仓库入口与简历查看入口。

## 设计方法

作品集以视觉稿、内容规范和浏览器中的真实布局为共同依据。尺寸、字体、间距与层级通过实际页面进行校准；项目之间使用统一的导航和 Z 型阅读顺序，保证用户可以自然地浏览、进入和返回不同项目。

对于静态稿无法完整表达的部分，使用克制的悬浮、揭示和转场反馈补全交互，同时保留移动端的内容顺序与可访问性。

## 使用说明

建议按照以下顺序体验：

1. 从首页 Hero 进入作品流。
2. 通过作品卡片进入对应项目详情页。
3. 在详情页使用顶部项目导航或底部 `NEXT PROJECT` 按阅读顺序切换项目。
4. 在 `ABOUT ME` 查看个人介绍、经历与奖项，并通过“查看简历”在新窗口打开 PDF。
5. 使用 `LET'S TALK` 或 footer 社交链接访问联系入口。

## 文件结构

- `index.html`：首页、作品流、About Me 与 footer。
- `app-redesign.html`、`web-design.html`、`other-items.html`、`ip-design.html`、`mood-cloud.html`：项目详情页。
- `styles.css`：首页视觉、响应式布局与交互状态样式。
- `ip-design.css`、`ip-design.js`：详情页共用样式与项目交互脚本。
- `script.js`：首页导航、作品流、联系入口与动效逻辑。
- `assets/projects`：各项目图片资源。
- `assets/images`、`assets/svg`：Hero、About、联系与通用视觉资产。
- `assets/docs/lin-yuhang-resume.pdf`：个人简历。

## 项目定位

这份作品集既是阶段性设计成果，也是设计与实现之间的沟通媒介。它将分散在视觉稿、标注和项目说明中的关键规则整理为统一、可操作的浏览体验，方便在作品展示、面试沟通和后续迭代中快速验证设计意图。
